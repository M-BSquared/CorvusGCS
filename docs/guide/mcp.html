Tools

AI clients (MCP)

Corvus can hand an AI client such as OpenCode a set of tools: read the vehicle, its parameters and its mission, and, as far as you allow it, change parameters, fly missions and points, or steer the vehicle directly. It does this through the Model Context Protocol (MCP), which most coding and chat agents speak. Nothing of it is on until you switch it on, and you decide each kind of act on its own.

Setting it up

  1. Open Settings, Connections and scroll to MCP server. Switch it on. The card says who is connected and how many permissions are on.
  2. Press Permissions and switch on what the client may do (see below).
  3. Press Connect an AI client, which is there only while the server is on. Press Copy for OpenCode and paste the block into opencode.json in your project folder, or into ~/.config/opencode/opencode.json for every project.
  4. Start OpenCode in that folder. /mcp in OpenCode shows corvus as connected. Ask it, for example, what the battery says.

The block it copies looks like this, with your address and your token:

{
  "$schema": "https://opencode.ai/config.json",
  "mcp": {
    "corvus": {
      "type": "remote",
      "url": "http://127.0.0.1:8000/mcp",
      "enabled": true,
      "oauth": false,
      "timeout": 60000,
      "headers": { "Authorization": "Bearer <token>" }
    }
  }
}

timeout is longer than OpenCode's default of 30 seconds on purpose: a call that waits for you to allow it can take up to 45. Any other client that speaks MCP over HTTP (Streamable HTTP) works the same way: the address, and the header Authorization: Bearer with the token.

Address
The port is the one Corvus runs on, 8000 unless it was taken when Corvus started and it had to move on. Only this computer can connect: the server answers nothing that comes from the network, even when Corvus itself is reachable there.
Token
Like a password for the MCP server, shown only on this computer. It is kept in ~/.corvus/mcp-token, readable only by you, and never in the config file or a settings export. New token (the arrows beside it) makes another one; clients holding the old one are refused from then on.

What the AI client may do

One switch per kind of act. A tool whose switch is off is not even offered to the client, so it cannot try. Reading is on as soon as the server is; everything that changes the vehicle starts off.

SwitchTools
Read telemetry and statusget_vehicle_state, list_vehicles, get_capabilities, list_flight_modes, download_mission
Read parameterslist_parameters, get_parameters, download_parameters
Change parametersset_parameter, only for names the connected firmware reported
Missionsupload_mission, start_mission, clear_mission. Starting a mission arms the vehicle.
Arm and disarmarm, disarm
Takeoff, land, return, hold and flight modetakeoff, land, return_to_launch, hold, set_flight_mode, set_home
Fly to a pointfly_to, one point or several, at a height above home
Direct controlmanual_control, set_velocity, stop_control
Other MAVLink commandssend_command, from the list get_capabilities names
Plugin toolsThe tools of the plugins switched on under Plugin tools

Every tool goes through the same checks as your own buttons, with the same PX4 and ArduPilot sequences behind it, so an AI client cannot do anything a button could not. What a client does is written to the MAVLink console with its name, and anything refused goes to the notification board as well.

Other vehicles of the fleet, at the top of the same dialog, is off by default: the client then acts only on the vehicle you fly. On, its tools take a vehicle id from list_vehicles, as a plugin's do.

Ask me first

Every switch that changes something has Ask me first below it. It starts on for parameters, missions, arming, flight commands, direct control and other commands. With it on, a call from the client opens a dialog in Corvus with the client's name and what it wants to do, and nothing is sent until you press Allow. Refuse, or 45 seconds without an answer, tells the client no. A call that needs your answer is refused outright when no Corvus window is open to ask in.

Direct control and the watchdog

A vehicle flown by sticks or velocity needs new input several times a second, and an AI client answers in seconds. So each manual_control or set_velocity call says how long it lasts, at most 5 seconds (1 by default). Corvus repeats it five times a second for that long, and if no new call has come in by then, the vehicle is put in hold. A client that goes quiet stops the aircraft. With Ask me first on, you are asked once when it takes control, not for every input; once it has stopped, the next input asks again.

On the map

While a client is connected and may change something, a pill under the flight bar says AI client connected. It turns red and reads AI client flying while it steers directly, and pulses while it waits for your answer. Its Stop button switches every permission that changes the vehicle off at once, refuses whatever is waiting, and puts a vehicle under direct control in hold. Reading stays on, so the client can still see what happened. Switching the server off has the same effect on what is waiting.

Plugin tools

Plugins can add tools of their own. The client sees them only with Plugin tools on, the plugin's own switch on in the list at the end of the Permissions dialog, and whatever the plugin itself asks for. Schwalby, for instance, has two switches in its gear: one lets the client add buttons that run on this computer, the other lets it press buttons (see Schwalby). A plugin's tools run in the Corvus window, so they exist only while one is open. How to write one is in Tools for an AI client.

What the switches cannot do

The switches decide what the client may do through MCP. Many coding agents can also run commands on your computer. Such an agent could reach Corvus another way, as any program on this computer can, so allow those commands only in a project where you trust it. The MCP server is a set of instructions an agent follows, held to on the channel it was given; it is not a sandbox.

The settings travel with a settings export under Connections; the token never does. The endpoints are listed in Files, settings and variables and in the corvus/mcp.py module docstring.
