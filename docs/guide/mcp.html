Tools

AI clients (MCP)

Corvus can hand an AI client such as OpenCode a set of tools: read the vehicle, its parameters and its mission, and, as far as you allow it, change parameters, fly missions and points, steer the vehicle directly, or draw on your map. It does this through the Model Context Protocol (MCP), which most coding and chat agents speak. The server for other programs is off until you switch it on, and you decide each kind of act on its own.

At your own risk. A language model makes mistakes. What you allow it may do at any moment, also wrongly, up to flying the aircraft. A model may misread what you wrote, and it may follow text it reads in a log, a chat or a web page. Corvus checks and limits what reaches the aircraft, but it cannot judge whether an act makes sense. Leave off what you do not need, keep Ask me first on, keep your hands on the controls, and try it with the propellers off. You connect an AI client and allow its acts at your own risk. Nothing of this is needed to fly with Corvus.

AI Chat needs no setting up

The AI Chat plugin signs in by itself, with a token Corvus makes anew at every start and keeps off the disk. It does so while the server below is off, so nothing has to be switched on for it. The permissions hold for it too, with one difference: what is off is offered to it all the same, and Corvus asks you each time before anything happens.

AI Chat (under the server switch)
Off, the plugin gets no tools.
Ask me for what AI Chat may not do (in the Permissions dialog)
Off, AI Chat gets only what you switched on there. Stop on the map switches it off.

Setting it up

  1. Open Settings, Connections and scroll to MCP server. Switch it on. The card says who is connected and how many permissions are on.
  2. Press Permissions and switch on what the client may do (see below).
  3. Press Connect an AI client, which is there only while the server is on. Press Copy for OpenCode and paste the block into opencode.json in your project folder, or into ~/.config/opencode/opencode.json for every project.
  4. Start OpenCode in that folder. /mcp in OpenCode shows corvus as connected. Ask it, for example, what the battery says.

The block it copies looks like this, with your address and your token:

{
  "$schema": "https://opencode.ai/config.json",
  "mcp": {
    "corvus": {
      "type": "remote",
      "url": "http://127.0.0.1:8000/mcp",
      "enabled": true,
      "oauth": false,
      "timeout": 60000,
      "headers": { "Authorization": "Bearer <token>" }
    }
  }
}

timeout is longer than OpenCode's default of 30 seconds on purpose: a call that waits for you to allow it can take up to 45. Any other client that speaks MCP over HTTP (Streamable HTTP) works the same way: the address, and the header Authorization: Bearer with the token.

Address
The port is the one Corvus runs on: 8000, or the HTTP port in its config if you changed it. It stays the same from one start to the next, so the block keeps working after a restart. Only when another program already holds that port does Corvus take the next free one, and then the block shows the new address and needs copying again. No other computer can connect: the server answers nothing that comes from the network, even when Corvus itself is reachable there.
Token
Like a password for the MCP server, shown only on this computer. It is kept in ~/.corvus/mcp-token, readable only by you, and never in the config file or a settings export. New token (the arrows beside it) makes another one; clients holding the old one are refused from then on.

Plugin toolsThe tools of the plugins switched on under Plugin tools

Every tool goes through the same checks as your own buttons, with the same PX4 and ArduPilot sequences behind it, so an AI client cannot do anything a button could not. What a client does is written to the MAVLink console with its name, and anything refused goes to the notification board as well.

Other vehicles of the fleet, at the top of the same dialog, is off by default: the client then acts only on the vehicle you fly. On, its tools take a vehicle id from list_vehicles, as a plugin's do.

Ask me first

Every switch that changes something has Ask me first below it. It starts on for parameters, missions, arming, flight commands, direct control, the geofence, the camera and other commands. With it on, a call from the client opens a dialog in Corvus with the client's name and what it wants to do, and nothing is sent until you press Allow. Refuse, or 45 seconds without an answer, tells the client no. A call that needs your answer is refused outright when no Corvus window is open to ask in.

Direct control and the watchdog

A vehicle flown by sticks or velocity needs new input several times a second, and an AI client answers in seconds. So each manual_control or set_velocity call says how long it lasts, at most 5 seconds (1 by default). Corvus repeats it five times a second for that long, and if no new call has come in by then, the vehicle is put in hold. A client that goes quiet stops the aircraft. With Ask me first on, you are asked once when it takes control, not for every input; once it has stopped, the next input asks again.

On the map

While a client is connected and may change something, a pill under the flight bar says AI client connected. It turns red and reads AI client flying while it steers directly, and pulses while it waits for your answer. Its Stop button switches every permission that changes the vehicle off at once, refuses whatever is waiting, and puts a vehicle under direct control in hold. Reading stays on, so the client can still see what happened. Switching the server off has the same effect on what is waiting.

Drawings

draw_marker, draw_line, draw_circle and draw_area draw one thing each, which small models do best. draw_on_map draws several at once: lines, arrows, areas, circles, sectors (a field of view), markers and text on the Home map, flat and in 3D. Places can be coordinates, or relative to the vehicle or home: 200 m along its heading, 50 m north of home. So you can ask for an arrow from the aircraft to the search area, look at it, and then have it flown along with fly_drawing. A pill on the map says how much is drawn and Clear takes all of it away. Drawings last until Corvus is closed. The map holds at most 200.

Asking for telemetry

"How full is the battery?", "Is the GPS good?", "How much does it vibrate right now?": get_telemetry answers a group of values with the unit in each name: overview, position, attitude, speed, battery, gps, link, mission, health and vehicle. With seconds it watches that long (20 at most) and answers the smallest, the largest and the mean value too. A value the vehicle does not report is null.

Planning missions

plan_mission puts a route into the mission planner: "plan a square of 200 m around the aircraft at 40 m". plan_survey covers an area back and forth. get_mission_plan reads what you have drawn there yourself, with the warnings the planner gives about it. edit_mission_item moves a point, changes its height, speed and so on or its place in the order, remove_mission_item takes it out, and set_mission_plan sets the name, the start and the aircraft. open_mission_plan opens a saved mission or reads the one the vehicle holds, and save_mission saves what is in the planner (with the Missions permission). Nothing is sent to the vehicle: you look at the plan, change what you like, and upload it, or have it uploaded with upload_mission_plan, which needs the Missions permission. When the client replaces a plan of yours, the planner says so and Take mine back brings yours back. A client that may open pages brings the planner to the front, also when its page is off under Settings, Layout; it then stays until Corvus is closed.

Showing places and pages

show_on_map moves the map anywhere: to coordinates, to a place relative to the vehicle or home, to drawings, or to a place by its name ("show me Neubiberg", which needs internet). The client can choose the zoom and bring the map to the front. open_page opens a page: "open the plugin settings", "show the parameters", "switch to 3D". It presses nothing on it. Corvus stays where it is while a page with unfinished work is open (parameters, a calibration, a firmware) and puts a line on the notification board instead.

Plugin tools

Plugins can add tools of their own. The client sees them only with Plugin tools on, the plugin's own switch on in the list at the end of the Permissions dialog, and whatever the plugin itself asks for. These plugins have switches of their own, in their gear under Settings, Plugins. All are off at first.

SchwalbyAI clients may add buttonsAdd buttons that run on this computer, each waiting for you to allow it

When Corvus asks you about a plugin's tool, the question shows what it is called with. A plugin's tools run in the Corvus window, so they exist only while one is open. How to write one is in Tools for an AI client.

What the switches cannot do

The switches decide what the client may do through MCP. Many coding agents can also run commands on your computer. Such an agent could reach Corvus another way, as any program on this computer can, so allow those commands only in a project where you trust it. The MCP server is a set of instructions an agent follows, held to on the channel it was given; it is not a sandbox.

The settings travel with a settings export under Connections; the token never does. The endpoints are listed in Files, settings and variables and in the src/core/src/mcp module documentation.
